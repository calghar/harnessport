## Why

Cursor's CLI reads permission rules from `.cursor/cli.json` and runs formatters from its `afterFileEdit` hook, but harnessport declares both `none` and drops them. A Claude project's `deny` rules and formatters therefore never reach Cursor.

## What Changes

- **ADDED** Permission export to `.cursor/cli.json` (project file, `permissions.allow` and `permissions.deny`):
  - Claude `Bash` pattern `*` → `Shell(*)`, exact, allow or deny.
  - Claude `Bash` deny with a pattern → `Shell(<first token>)`, **lossy**: Cursor matches the whole command base, so the deny covers more commands.
  - Claude `Bash` allow with a pattern → **dropped**: `Shell(<first token>)` would allow more commands than the rule.
  - Claude `Read`, `Write`, `Edit`, `WebFetch` deny → **blocked**: Cursor's matching of these patterns is not verified to be no narrower than Claude's.
  - `ask`, and tools with no Cursor rule type → **blocked** through `permissionStatus`.
- **ADDED** Formatter export: each Claude formatter with a shell-free command becomes an `afterFileEdit` entry in `.cursor/hooks.json` that runs `.cursor/hooks/harnessport-format.mjs <glob> <command>`. Formatters needing a shell stay dropped, as on Claude.
- **ADDED** Formatter import: `afterFileEdit` entries written by harnessport are read back into the canonical formatter list. Other `afterFileEdit` entries are reported as dropped on import.
- **MODIFIED** `.cursor/hooks.json`: holds `afterFileEdit` next to `preToolUse`, still one file written once.
- **MODIFIED** Formatter runner source and shell-syntax helpers move from `src/converters/claude.ts` to `src/converters/formatter-runner.ts`. The Claude runner file stays byte-identical.
- **NOT IN THIS CHANGE**: permission import from `.cursor/cli.json`. The `permission` capability stays `none` until it exists (see design, open question 1).

**BREAKING:** none. Conversions into a Cursor directory gain files; an existing `.cursor/cli.json` or `.cursor/hooks.json` with different content is refused as today and needs `--force`.

## Impact

- **On-disk output (Cursor target only):** new `.cursor/cli.json` (permissions), new `.cursor/hooks/harnessport-format.mjs`, new `afterFileEdit` key in `.cursor/hooks.json`.
- **CLI:** no flag, exit-code, or stdout-format change. A blocked Claude `Read`/`Edit`/`WebFetch` deny now exits `2`, as blocked items already do.
- **Security:** an allow is never widened: a Claude allow that Cursor cannot express exactly is dropped, so Cursor prompts instead. A deny is never narrowed: a deny that Cursor would match narrower, or cannot be shown to match equally, is blocked. The Cursor deny that remains (`Shell(<base>)`) is broader than the source, so it is reported lossy.
- **Scope of enforcement:** `.cursor/cli.json` is documented for the Cursor CLI. Whether the Cursor IDE reads it is not verified; the fidelity reason for permissions says so.
- **Dependencies:** none added.
